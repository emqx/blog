[NeuronEX](https://www.emqx.com/zh/products/emqx-neuron) 4.0 现已正式发布。

与通常不断增加新功能的做法不同，这一次我们主动做了减法：移除了内置数据库、数据探索模块、Node-RED 和 AI 助手——这些功能并无问题，只是与工厂已有的软件工具存在重叠。

新一代工业连接服务器应专注于连接设备、在边缘侧清洗数据，并将干净可靠的数据交付给专业系统存储。

因此，NeuronEX 4.0 将重点放回工业连接能力本身：新增 Brother 和 Mazak 数控机床驱动，优化 Beckhoff ADS、Siemens 和 EtherNet/IP 驱动，并简化标签列表的创建流程。

## 移除了哪些功能？为什么？



| 移除的功能                                                   | 原因                                                         |
| :----------------------------------------------------------- | :----------------------------------------------------------- |
| **数据探索功能**：包括内置 Datalayers 数据库、基于该数据库的查询分析功能，以及负责向数据库写入数据的 DataStorage 应用 | 需要存储历史数据的工厂通常已经部署了 Historian 或时序数据库。规则引擎可以将数据写入 InfluxDB、SQL 数据库和 Redis 等系统，直接利用客户现有的数据基础设施。 |
| **内置 Node-RED**                                            | 规则引擎可以通过 SQL 完成类似的工作。SQL 规则以文本形式存储，便于通过 Pull Request 审查、比较版本差异，也方便后续维护。可视化画布在这些方面不够便利。 |
| **LLM 功能**：包括 AI 助手和 AI 问答                         | 模型推理功能继续保留。此次移除的是基于大语言模型的相关功能，这类能力更适合部署在云端，而不是工厂现场的设备机柜中。 |
| **Syslog 转发**                                              | 监控指标可以发送到 Prometheus Pushgateway，告警可以通过 Webhook 发送，满足原有的监控需求，也更便于接入现有监控工具。 |

Docker 镜像也进行了精简，移除了不必要的系统依赖。标准镜像的体积缩小至原来的约四分之一。

镜像更小，意味着需要维护和修补的组件更少，安全审查更简单，新工程师也能更快上手。

## 新增功能与优化



### 新增两款数控机床驱动



- **Brother CNC 驱动：**通过以太网或串口连接 Brother 加工中心，使用 Brother NC 协议采集轴坐标、主轴和刀具数据、报警信息、工件计数、程序编号、PLC 设备数据及刀具偏置量。
- **Mazak CNC 驱动：**通过 UDP 接收 Mazak 数控机床发送的状态数据包，并将各字段转换为数据标签。该驱动不会主动向机床发送请求。

两款驱动均为只读，不会向机床写入数据。它们与现有的 FANUC、Siemens、Mitsubishi、HEIDENHAIN 等 CNC 驱动共同扩展了 NeuronEX 的数控设备接入能力。

与其他 CNC 驱动一样，这两款新驱动需要试用许可证或商业许可证，免费许可证不包含 CNC 驱动的使用权限。

### 优化现有驱动



- **Beckhoff ADS：**支持从 TwinCAT 2 和 TwinCAT 3 生成的 TPY 文件导入标签。
- **Siemens：**支持数组数据类型。
- **EtherNet/IP：**扩大设备兼容范围，支持在更多类型的设备上读取和写入标签。

### 更方便地管理标签列表



- **CSV 导入和导出：**现在可以通过 CSV 文件导入和导出标签。标签列表可以直接用电子表格编辑、在不同实例之间复制，也可以纳入版本控制。
- **在 OPC UA 浏览器中搜索标签：**浏览 OPC UA 服务器的地址空间时，可以直接搜索和筛选标签。即使服务器规模较大，也能快速找到目标节点，无需逐层查找。

## 哪些功能保持不变？



除了新增和移除的功能，以下核心能力在 NeuronEX 4.0 中均保持不变。

- **所有 3.x 版本的驱动均予以保留。**NeuronEX 继续支持 70 多种工业协议，覆盖 PLC、数控机床、电力与能源标准及楼宇系统，并支持以太网和串口通信。
- **数据采集机制保持不变。**标签按采集组管理，每个采集组可以设置独立的轮询周期。同一采集组的数据可以供多个订阅应用共享。增加一个数据输出目标，不会增加设备端的读取次数。
- **规则引擎保持不变。**规则引擎继续提供基于 SQL 的流式处理能力，支持 160 多个函数和五种窗口类型。基于 ONNX 模型的推理功能也继续保留。

## 两种容器镜像，体积大幅缩小



| 镜像                             | 包含内容                                            | 下载体积    | 适用场景                         |
| :------------------------------- | :-------------------------------------------------- | :---------- | :------------------------------- |
| `emqx/neuronex:<version>`        | 标准镜像，包含 Python 运行时和规则引擎的 Python SDK | 小于 110 MB | 默认镜像；运行 Python 插件时使用 |
| `emqx/neuronex:<version>-extend` | 标准镜像，额外包含 FFmpeg 和 ONNX                   | 小于 275 MB | 模型推理和视频数据源场景         |

在 v3.9 中，标准镜像约为 450 MB，包含模型推理功能的 `-ai` 镜像则超过 700 MB。

镜像体积缩小后，在工厂网络较慢时下载更快，也能为资源有限的边缘网关节省空间。

`-ai` 镜像现已移除，模型推理功能改由 `-extend` 镜像提供。如果当前正在运行模型，请在升级前修改镜像标签。


## 升级前检查清单



升级前，建议按以下顺序完成检查：

1. **确认已移除的功能是否仍在使用。** 包括数据探索、内置数据库、DataStorage 应用、Node-RED、AI 助手和 Syslog 转发。如有依赖，请先规划替代方案。
2. **调整模型推理使用的镜像。** 模型推理运行时现已包含在 `-extend` 镜像中。
3. **同时挂载** `data/` **和** `plugins/`**。** 避免替换容器后丢失已安装的插件。
4. **备份相关文件。** 除上述两个目录外，还应备份 `etc/` 下经过修改的文件。

## 快速开始



如果你是第一次使用 NeuronEX，可以先安装软件并连接一台设备，快速体验其功能。

NeuronEX 提供永久有效的免费许可证，支持 30 个数据标签，无需申请即可使用。试用许可证有效期为 15 天，支持最多 1,000 个标签，并开放所有驱动、应用和完整的数据处理引擎。

试用许可证需要绑定硬件 ID，而容器没有硬件 ID。如果使用容器部署，请联系 EMQ 获取不绑定硬件 ID 的许可证。

**一行命令即可安装：**

```
curl -fsSL emqx.sh/neuron | bash
```

安装脚本会自动选择 `.deb`、`.rpm`、`tar.gz` 或 Docker 安装方式。NeuronEX 支持 Linux，可运行在 64 位 x86、32 位 ARM 和 64 位 ARM 平台上，既能部署在边缘网关，也能部署在服务器上。

如果你正在从 KEPServerEX 或 Litmus Edge 迁移，可以使用 EMQ 提供的[在线迁移工具](https://www.emqx.com/en/products/emqx-neuron/migrator)，将原有产品的驱动配置和标签配置转换为 NeuronEX 可导入的文件。建议先让新旧系统并行运行，完成对比验证后再切换。
