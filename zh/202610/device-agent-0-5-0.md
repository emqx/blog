> [Device Agent](https://www.emqx.com/zh/device-agent) 是 EMQ 开发的 MQTT 驱动的 AI 设备智能体平台。用自然语言描述设备的能力，平台在几分钟内即可生成包含设备规格、端侧 SDK、在线模拟器以及语音、视觉、IM 等多通道交互入口的完整设备智能体。

Device Agent 0.5.0 现已发布。

该版本新增 IoT 平台集成，已接入 IoT 平台的设备可以直接通过自然语言查询、控制和自动化处理。工作流新增可视化编辑器和 Jev 决策节点；对话新增配置总览、长期记忆、语音反馈和对话内 A2A 协作；企业平台提供运行监控、设备 AI 额度和 License 授权管理。

## IoT 平台集成



已经在 IoT 平台上管理的设备，不必迁移数据或改写模型，就能获得自然语言查询、控制和自动化能力。

0.5.0 新增 **IoT 平台集成**，自建或第三方 IoT 平台都可以通过适配接入，并沿用平台的原生物模型、设备身份和操作方式：物模型说明设备有哪些状态、允许哪些动作、参数怎么填，平台连接负责读取数据和实际执行。接入后，同一批设备能力可以用于对话、工作流、定时任务和 A2A 协作。

![image.png](https://assets.emqx.com/images/7b9451da18a9476a2446f2d4ab0077b1.png)

例如，设备模型提供了温度和运行模式时，可以直接请求：

> 查看这台设备的当前温度和运行模式，说明最近上报中有没有需要关注的异常。

不同平台的控制方式不同：设置目标温度时，有的平台调用服务，有的平台更新期望状态。Device Agent 会按当前接入方式调用对应操作，你可以核对目标设备、操作参数、平台回执和设备最新状态。状态面板新增期望状态、状态差异和枚举说明，并显示平台提供的命令历史和设备任务记录。

设备和状态数据仍由平台提供，具体能力取决于平台开放的接口。以已适配的 ThingsNeural 为例：登录授权后会自动填写连接配置，凭证过期时引导重新绑定；通过**同步产品**根据原生模型生成或更新设备智能体，同步时保留本地配置，失败时显示原因；还可以按时间范围查询属性和事件历史，并对返回的记录做分时统计。

新设备仍可以通过 SDK 或 MQTT 直连。本版本新增储能、光伏逆变器建模参考，SDK 和模拟器也适配了平台的原生模型与协议。在模拟行为预览中，可以先确认一条命令会如何改变模拟状态，再开始硬件程序开发。

接入方式见：[IoT 平台集成](https://docs.emqx.com/zh/device-agent/latest/integrations/iot-platform.html)。

## 工作流与 Jev 决策



自动化流程可以在图上直接调整，固定规则和 Agent 判断能放进同一条流程。

0.5.0 新增**可视化编辑器**：通过自然语言生成流程后，可以直接在图上增删节点、修改属性和调整连线。Agent 节点可以限定允许使用的动作、工具和技能；动作节点新增 IM 通知、设备状态更新、设备检查和平台设备任务。

以储能场景为例，异常、离网或低电量这类明确条件走固定分支；接入天气、电价或调度计算工具后，再由 Agent 结合这些信息选择后续策略。创建时可以检查流程结构，运行后可以查看实际路径、调用参数和每一步的结果。

### Jev 决策节点



告警分流这类判断需要读懂文字，结果却只是几个选项之一。本版本接入 **TypeSafe 的 Jev 决策模型**：开发者定义问题和候选选项，Jev 根据事件内容选择其一，Device Agent 再沿对应出口执行。这类判断不必每次都经过完整的 Agent 流程，高频判断的调用开销更容易控制。

例如，检测终端上报「设备已经恢复，连续三次检测通过」和「同一故障反复出现，仍在等待人工复核」，后续处理应该不同。可以这样描述工作流：

> 收到检测异常告警时，判断故障是否已经恢复。已恢复且后续检测正常，只记录事件；仍未恢复或反复发生，发送运维通知；信息不足时，交给 Agent 整理缺少的信息和建议检查的项目。

![image.png](https://assets.emqx.com/images/1e328fcc2a2a2b4faa6acde245fd5b19.png)

决策节点固定提供**证据不足**出口，运行记录会显示选项、置信度和各选项概率。

明确的数值阈值仍用条件分支，需要查询历史、解释原因或多步处理时交给 Agent；需要读懂描述、在几个选项中做选择时适合交给 Jev，例如：

| 场景           | 让 Jev 选择                                 | 为什么适合 Jev                                           |
| :------------- | :------------------------------------------ | :------------------------------------------------------- |
| 告警分级与降噪 | 紧急 / 维护 / 误报                          | 告警量大、误报多，单一阈值容易漏判或误判                 |
| 故障初步诊断   | 传感器故障 / 网络问题 / 供电问题 / 真实异常 | 选项可以来自设备手册或运维经验，每个出口对应一套处理步骤 |
| 事件分派       | 通知哪个团队、是否交给 Agent                | 先分流，只有复杂情况才交给 Agent                         |

本地部署还提供 **Jev 快捷指令**。选中设备后，输入「将采集间隔改为 2 秒，开启诊断日志」这类明确请求，Jev 会从模型已有的命令和参数中选择并下发。相对调整、自由文本参数和复杂请求仍交给智能体对话。配置与适用范围见：[Jev 决策模型](https://docs.emqx.com/zh/device-agent/latest/usage/jev.html)。

## 对话与语音



### 配置总览



助手怎么回答、能听懂哪些术语、可以使用哪些工具，现在可以在一处按业务调整。

设备智能体新增**配置总览**，集中维护对话规则、时区、识别热词、语音工具范围、回复与反馈，以及设备能力和 A2A 设备绑定，提供配置图和列表两种视图。

例如，车间巡检助手可以设置「先汇报当前状态，再说明异常，数值保留单位」，为设备名和业务术语添加热词，并只开放巡检需要的语音工具。对话规则只影响助手如何处理和表达信息，可以查询和执行的能力仍由设备模型定义。

![image.png](https://assets.emqx.com/images/629eed0d1ca640a8cbbf8cae92343179.png)

### 语音反馈



语音回复更早开口，等待时也有反馈。模型调用工具前的开场回复会先播报，不必等工具执行完成；支持流式合成的语音服务可以边生成回答边播报。

需要等待时，可以按请求类别配置等待话术和响应超时提示，例如在查询开始时提示“正在查询设备状态，请稍等”。

本版本还加入问题匹配和音频复用：重复出现的查询可以按配置匹配处理，常用反馈音频可以复用。企业平台还可以预加载允许的只读查询；设备控制仍按实际请求执行。

语音工具出错后的恢复、回答上下文和中断处理也有改进，上一轮语音对后续对话的干扰更少。配置见：[设备智能体配置](https://docs.emqx.com/zh/device-agent/latest/usage/agent-configuration.html)。

### 长期记忆、上下文与模型推理



偏好说一次就能沿用，长对话也可以持续进行。0.5.0 支持保存、查看和删除长期记忆，例如：

> 记住：设备告警先说明原因，再给出处理建议。

保存成功后，后续对话可以参考这条偏好，也可以随时要求查看或忘记。长期记忆在当前部署的设备和会话之间共享，适合稳定的偏好和已确认的事实；温度、在线状态等实时信息仍从设备或平台查询。

对话界面会显示上下文占用，并在自动压缩时提示，较长的对话可以在保留近期内容和摘要的基础上继续。清空对话时会归档历史，长期记忆保留。

![image.png](https://assets.emqx.com/images/39188ee8ba7f8b651477b39ce322f59c.png)

模型配置支持启用推理，并选择当前模型支持的推理等级；模型返回思考内容时，可以在对话中展开查看。使用方式见：[对话与记忆](https://docs.emqx.com/zh/device-agent/latest/usage/conversations-memory.html)和[大模型配置](https://docs.emqx.com/zh/device-agent/latest/operate-reference/configuration/model-config.html)。

## A2A：在设备对话中协作



跨设备的查询和控制，不必再切换到 A2A 工作区，在主控设备的对话或语音中就能完成。

0.4.0 提供了 A2A 场景和任务；0.5.0 则支持直接在设备的文字或语音对话中，把任务分派给已绑定的目标设备智能体，并把结果返回原对话。

以家庭中控为例，在**配置总览 → A2A 设备绑定**中，为一台主控关联客厅温控器、卧室温控器和卧室风扇。每台主控的绑定单独保存，同一智能体下的多台设备也可以分别关联。

![image.png](https://assets.emqx.com/images/6dbbdfdab42cf3d801836c10178c1deb.png)

选中这台主控后，可以输入或说出：

> 查看客厅和卧室温控器的当前温度，并查看卧室风扇的运行状态。

主控会在绑定范围内找到目标，分别查询后汇总结果。A2A 协作需要已启用 A2A 注册表的 EMQX 6.2.0 或以上版本；语音协作还需要完成语音接入并开放对应工具。设备模型保存或平台同步后，已发布的能力卡片会随之更新。配置步骤见：[A2A 多智能体协作](https://docs.emqx.com/zh/device-agent/latest/usage/a2a.html)。

## 适用于生产环境的企业平台



从功能验证进入生产后，运行状态、使用成本和授权容量都可以集中掌握。

此前，Device Agent 仅支持本地部署，更适合单机和边缘场景。自 0.5.0 版本起，我们提供面向生产环境的商业化平台，可以部署在企业自有基础设施中，集中运行和管理设备智能体。

企业平台可将任务、会话和执行记录持久保存，请求接入和智能体执行可以分别扩展资源。服务中断后，可以先查询已有的运行结果，再决定是否重新提交，避免重复下发设备操作。平台可部署在专用 Linux 服务器或已有的 Kubernetes 环境中，也支持隔离网络环境交付。

**运行监控**提供平台总览、AI 用量、集群、连接与会话、响应时延五个视图。运维人员可以查看任务结果、排队情况、模型调用和服务状态，并按设备查看 Token、语音用量、累计用量和费用估算。语音按轮记录各阶段耗时，可以定位变慢发生在哪个环节。

![image.png](https://assets.emqx.com/images/c2906c2e12ea09f5d96066cd8f61089b.png)

*界面示例，数据仅用于展示*

**设备 AI 额度**支持人民币或美元计价，可以为设备配置独立预算、扣费规则和模型倍率，并查看或调整设备余额。监控中的费用是估算值，实际费用以服务商账单为准；设备余额按配置的扣费规则扣减。

**License 授权**由管理员导入签名授权文件，按每分钟智能体请求数（RPM）和有效期管理整个部署。所有设备和执行节点共享授权额度，可以按需扩容或续期。平台授权、设备 AI 预算与第三方模型和语音服务额度分别管理。

私有部署与商业授权见：[平台概览](https://docs.emqx.com/zh/device-agent/latest/platform/overview.html)。

## 改进



- 新增豆包 Ark 模型提供商，完善 Cloudflare 配置，更新 DeepSeek Flash、Kimi 的模型选择与推理选项，并扩展阿里云语音识别、语音合成模型及对应音色。
- 改进浏览器模拟器的连接保持、重连和参数映射兼容性，连续调试设备行为更稳定。
- 经 IoT 平台接入的设备，更新设备状态或调用设备任务不再需要审批，仍会防止重复执行。
- 企业平台中，绑定设备的定时任务到期后，提醒内容会通过 MQTT 发送到该设备，与设备对话回复使用同一通道；本地部署中，到期结果仍显示在控制台。
- 改进手机工作区、聊天布局、历史消息分页和回复语言匹配。
- 导入技能压缩包时显示校验错误，方便定位无效内容。
- 提供 Docker 镜像安装入口，可以使用数据卷保存运行数据。

## 修复



- 修复从不同目录启动服务后会话历史丢失的问题。
- 修复设备状态和事件查询的时间问题：按服务器时区解析时间、返回完整的 UTC 时间，并避免查询最新事件时时间范围为空。

## 升级方式



已安装的用户，先备份运行数据和配置，停止当前服务后执行：

```
device-agent update
device-agent --version
```

确认版本显示 `0.5.0` 后，再运行 `device-agent` 启动。

首次安装，macOS 和 Linux：

```
curl -fsSL https://emqx.sh/device-agent | sh
device-agent --version
```

Windows PowerShell：

```
irm https://emqx.sh/device-agent.ps1 | iex
device-agent --version
```

使用 Docker：

```
docker pull emqx/device-agent:0.5.0

docker run -d --name device-agent --restart unless-stopped \
  -p 127.0.0.1:3000:3000 -p 127.0.0.1:3001:3001 \
  -e AGENT_GATEWAY_HTTP_HOST=0.0.0.0 -e VOICE_HOST=0.0.0.0 \
  -v device-agent-data:/home/device-agent/.device_agent \
  emqx/device-agent:0.5.0
```

启动后打开 `http://127.0.0.1:3000` 进入控制台。模型、MQTT 连接等配置见：[下载安装](https://docs.emqx.com/zh/device-agent/latest/installation.html)。

企业平台的升级由管理员按部署方案安排备份和服务更新。

完整变更与各平台安装包见：[Device Agent 0.5.0 Release](https://github.com/emqx/device-agent/releases/tag/0.5.0)。
